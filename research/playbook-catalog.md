# Playbook catalog (draft v1)

A playbook is one kind of work a user asks for. It composes units (the deliverables in `inventory-*.md`) from one or more books into a single procedure with one quality bar. Rule: one task has one playbook.

## Process playbooks (domain-independent)

| id | name | what it is |
| --- | --- | --- |
| P1 | Consulto | read-only question: what do the books say about X |
| P2 | Teardown | audit an existing asset against the rubric of its type |
| P3 | Diagnosi | a metric is failing: find the cause before changing anything |
| P4 | Esperimento | one metric, one change at a time, keep or revert |
| P5 | Programma | plan that chains several playbooks in dependency order |
| P6 | Brief di progetto | write or update the project context every playbook reads |
| P7 | Raccolta prove | pull external data and label each number as measured, documented or estimate |
